# 项目总览（OmniHand 2025 SDK）

## 在做什么

### 问题定义

本仓库用于提供 OmniHand 2025 灵巧手（O10/O12）的 SDK、示例程序与验证脚本，目标是让开发者可在 Linux/Windows 上完成设备控制、状态读取与联调验证。

### 系统边界

- 系统负责：
  - 提供 C++/Python API、Linux ROS2 适配、官方示例与验证脚本。
  - 提供运行环境安装脚本与发布包内依赖组织。
- 系统不负责：
  - 全身机器人运动规划与任务编排。
  - 设备制造层面的硬件故障诊断（仅覆盖已暴露接口可观测范围）。

### 输入 / 输出

- 输入：
  - 来自 API/ROS2/示例脚本的关节控制指令。
  - 通讯参数（CANFD/RS485、设备 ID、串口等）。
  - 验证脚本参数与运行配置。
- 输出：
  - 设备动作执行（关节角度控制、模式控制）。
  - 设备反馈数据（关节状态、服务返回、日志）。
  - 验证产物（日志文件、图表、终端结果）。

## 目的

### 目标场景与业务价值

- 机器人团队快速接入 OmniHand 设备，缩短从设备上电到可控的集成周期。
- 在部署前通过标准化验证脚本降低通讯、固件、接口兼容风险。
- 为 AI 与新同事提供可检索、可复用的工程化入口，降低交接成本。

### 可量化目标

- 在受支持环境中完成 SDK 安装与示例运行（成功率目标：可重复执行）。
- 验证脚本可产生日志并支持复现实验结果（同配置下结果可对比）。
- 关键关节控制与反馈链路保持稳定（无持续性失联或异常中断）。

## 如何实现

### 关键流程（主链路）

1. 执行安装脚本部署运行时依赖（Linux 常用入口：`linux/x64/install.sh`）。
2. 连接灵巧手与通讯适配器，确认权限与设备可见性。
3. 通过 API、ROS2 或示例脚本发送控制指令并读取状态。
4. 运行 `scripts/validation` 下验证脚本，分析日志与图表结果（例如 `l2_5_1_sensor_feedback_frequency.py` 区分采样频率与有效刷新频率，`l2_5_1_sensor_feedback_maxrate.py` 用于满速采样口径测试）。

### 核心依赖（外部服务/库/硬件）

- ROS2 Humble（Linux ROS2 链路）。
- Python 3.10（示例与验证脚本）。
- CANFD/RS485 适配器驱动与系统权限配置。
- 发布包内动态库与消息定义产物。

### 运行方式（命令、入口脚本、启动顺序）

- Linux SDK 安装：`bash linux/x64/install.sh`
- ROS2 环境加载：`source linux/x64/ros2/setup.bash`
- 验证脚本入口目录：`scripts/validation/`
- Python 示例入口目录：`linux/x64/python/demo/omnihand_2025/`

## 可行性与风险

### 前提假设

- 操作系统、架构、Python/ROS2 版本与发布包匹配。
- 通讯适配器驱动、设备权限、物理连接正确。
- 设备固件版本与当前 SDK 兼容。

### 已知限制

- ROS2 适配主要面向 Linux 发行结构。
- 实时表现受外部通讯质量与设备状态影响。
- 发布包缺失动态库时，消息/服务链路可能无法正常加载。

### 失败模式与降级方案

- 失败模式：设备初始化失败（权限/驱动/参数不匹配）。
  - 降级方案：先用最小示例验证通讯可用，再逐步恢复完整链路。
- 失败模式：ROS2 消息或服务加载失败（依赖缺失）。
  - 降级方案：先回退到 Python API 直连验证，确认设备侧正常后再修复 ROS2 依赖。

### 当前做不到

- 不保证在未验证的操作系统或未支持硬件组合上稳定运行。
- 不覆盖非 SDK 暴露范围内的底层硬件制造诊断能力。

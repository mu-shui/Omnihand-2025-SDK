# 功能文档维护规范

## 存放位置与命名

- 目录：`docs/project_detailed/`
- 文件命名：`<feature-name>.md`（英文短横线命名，例如 `joint-trajectory-control.md`）
- 文档语言：中文

## 何时必须新建功能文档

- 当仓库中增加了“原来没有的新功能”时，必须新建对应功能文档。
- 原有功能的修复、参数调整、局部扩展，不视为新功能，不强制新建文档（但应更新原功能文档日志）。
- 若在现有功能文档中找不到对应模块，默认判定为潜在新功能；若仍不确定，必须先询问用户是否新增功能模块。

## 功能文档必备结构（每个 `<feature-name>.md` 都必须包含）

1. 该功能的总实现目标
2. 实现步骤（必须标注“当前在哪一个步骤”）
3. 更新日志（精确到分钟，时间格式 `YYYY-MM-DD HH:mm TZ`）

## 推荐模板

可复制以下模板创建新功能文档：

```markdown
# <功能名称>

## 该功能的总实现目标

- （描述功能要解决的问题、目标输入输出、业务价值）

## 实现步骤（当前步骤：Step N）

1. Step 1：...
2. Step 2：...
3. Step 3：...

## 更新日志

### YYYY-MM-DD HH:mm TZ

- 变更内容：...
- 本次推进步骤：Step N -> Step N+1（或保持 Step N）
- 影响范围：...
- 关联路径：`path/to/file`
```
